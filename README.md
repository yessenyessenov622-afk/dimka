# Telegram inbox and task bot

Telegram-бот на TypeScript, Telegraf, PostgreSQL и Prisma. Пользователи пишут владельцу, а владелец отвечает из Telegram через постоянный режим ответа. Бот также ведёт историю диалогов и личный список задач с напоминаниями.

## Требования

- Node.js 20.19.0 или новее и npm.
- PostgreSQL 14 или новее (локально либо облачная база).
- Telegram-бот, созданный через [@BotFather](https://t.me/BotFather).
- Telegram numeric ID владельца.

Бот работает как постоянно запущенный Node.js процесс с long polling. Открытый HTTP-порт и webhook не нужны.

## Запуск в Windows через VS Code и PowerShell

1. Откройте папку проекта в VS Code. Встроенный терминал должен быть PowerShell.
2. Установите зависимости:

   ```powershell
   npm install
   ```

3. Создайте локальный файл настроек из шаблона:

   ```powershell
   Copy-Item .env.example .env
   ```

4. Заполните `.env`:

   ```dotenv
   BOT_TOKEN=токен_от_BotFather
   OWNER_TELEGRAM_ID=ваш_числовой_ID
   DATABASE_URL=postgresql://postgres:пароль@localhost:5432/telegram_bot?schema=public
   TIMEZONE=Asia/Almaty
   ```

   Перед запуском создайте пустую базу данных `telegram_bot` в PostgreSQL. Если пароль содержит специальные символы URL (`@`, `:`, `/`, `#` и другие), закодируйте их для URL.

5. Установите схему базы и соберите проект:

   ```powershell
   npm run db:migrate
   npm run build
   ```

6. Запустите бота:

   ```powershell
   npm start
   ```

   Для разработки с автоматическим перезапуском используйте `npm run dev`.

Файл `.env` исключён из Git. Настоящий токен храните только в нём локально и в переменных окружения сервера. Не вставляйте токен в исходники, переписку или репозиторий.

## Команды Telegram

### Пользователи

- `/start` — начать и прочитать уведомление о видимости данных.
- `/help` — инструкция.
- `/cancel` — отменить текущее действие.

Отправьте боту текст или вложение. Владелец получает его вместе с Telegram ID и доступными данными профиля; эти данные не показываются другим пользователям.

### Владелец

- `/admin` — панель владельца.
- `/inbox` — диалоги и непрочитанные сообщения.
- `/stats` — статистика пользователей, сообщений, диалогов и задач.
- `/tasks` — трекер задач.
- `/task_add` — создать задачу.
- `/settings` — часовой пояс.
- `/active` — показать текущего получателя.
- `/stop` — выключить режим ответа.

Telegram показывает пользовательский набор команд всем по умолчанию, а полный набор владельца — только в личном чате с владельцем. Списки настраиваются при старте через Telegram Bot API. Если меню не обновилось, отправьте боту `/start` и откройте меню команд ещё раз.

## Работа с диалогами

Под входящим сообщением владелец получает кнопки «Ответить», «История» и «Закрыть диалог». Копия сообщения отправляется отдельно, поэтому Telegram-вложения поддерживаются наряду с текстом. Кнопка «Ответить» включает постоянный режим: последующие текстовые сообщения и вложения владельца направляются выбранному собеседнику и сохраняются в истории. Переключитесь нажатием «Ответить» у другого пользователя или выключите режим кнопкой отмены либо `/stop`. Входящие сообщения не меняют выбранного собеседника.

Команды владельца продолжают работать во время ответа. Поиск в разделе входящих ищет по имени, username и числовому Telegram ID. Новые сообщения снова открывают ранее закрытый диалог.

## Задачи и напоминания

Создайте задачу кнопкой или через `/task_add`. Название и описание сохраняются в PostgreSQL; можно задать приоритет, срок и статус, изменить поля, удалить задачу, а также просматривать активные, выполненные, просроченные и все задачи. Статусы: новая, в процессе, выполнена и отменена. Напоминание приходит за 15 минут до срока. Время вводится как `ГГГГ-ММ-ДД ЧЧ:ММ` в установленном часовом поясе; значение по умолчанию — `Asia/Almaty`.

Текущая база хранит одно напоминание на задачу. При изменении срока напоминание планируется заново. Процесс должен работать постоянно, чтобы отправить его вовремя.

## Размещение на хостинге

Выберите хостинг, который предоставляет постоянно работающий Node.js worker и PostgreSQL. Подойдёт PaaS с фоновым процессом; статического хостинга недостаточно. Создайте PostgreSQL базу, затем задайте в настройках worker переменные `BOT_TOKEN`, `OWNER_TELEGRAM_ID`, `DATABASE_URL` и `TIMEZONE`.

Рекомендуемые команды хостинга:

- Версия Node.js: 20.19.0 или новее.
- Установка и сборка: `npm ci && npm run build` (для первого развёртывания без lock-файла можно использовать `npm install && npm run build`).
- Запуск: `npm run db:migrate && npm start`.

Миграция запускается перед стартом приложения, а затем бот начинает получать обновления через long polling. Настройте автоматический перезапуск worker при сбое. Если развёртываете несколько копий, оставьте polling включённым только у одной копии: Telegram Bot API допускает одного активного long-polling потребителя для токена.

## Проверка

```powershell
npm test
npm run build
```

Ключевые сценарии для ручной проверки после запуска:

1. Откройте бота с обычного аккаунта и отправьте текст, фото или документ; убедитесь, что владелец получает уведомление и вложение.
2. Нажмите «Ответить», отправьте несколько сообщений, затем нажмите «Отменить ответ». Повторите с другим пользователем, чтобы проверить переключение.
3. Откройте историю, профиль, закройте диалог; отправьте новое сообщение и убедитесь, что диалог открылся снова.
4. С обычного аккаунта вызовите `/admin`; доступ должен быть отклонён, а административные кнопки не должны появиться.
5. Создайте задачу со сроком, измените приоритет/статус, удалите тестовую задачу и проверьте напоминание на сроке менее 15 минут.
6. Перезапустите worker и проверьте, что история, задачи и текущий режим ответа восстановились.

Для локальной разработки тесты запускаются без Telegram токена и базы. Бот проверяет подключение к PostgreSQL при запуске, а все основные данные хранятся в мигрируемой Prisma схеме.
